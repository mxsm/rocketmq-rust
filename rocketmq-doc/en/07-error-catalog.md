# Canonical Error Catalog

This reference records the complete canonical error catalog implemented by
`rocketmq-error`. The catalog contains exactly 136 descriptors. It is the
single authority for stable error identity, classification, safe presentation,
recovery guidance, and boundary projections; domain facades and boundary
adapters do not maintain parallel policy tables.

The runtime source of truth is the declarative `define_error_catalog!` input in
`rocketmq-error/src/catalog.rs` and its domain modules. `ALL_DESCRIPTORS` fixes
the iterable order, while `rocketmq-error/tests/error_descriptor_catalog.rs`
freezes the complete descriptor snapshot. The table below is a documentation
projection of those two machine-checked sources, paired entry by entry in
`ALL_DESCRIPTORS` order.

## Descriptor fields

| Field | Meaning |
| --- | --- |
| Constant | Exported Rust constant naming the descriptor. |
| Code | Stable lowercase dotted semantic identity. Runtime values never form part of it. |
| Class | Broad operational class used for diagnostics and policy review. |
| Condition | Protocol-independent canonical condition. |
| Fault | Attribution to caller, dependency, remote peer, local resource, configuration, bug, or unknown origin. |
| Component | Low-cardinality owning component. |
| Public message | Fixed catalog-owned text; source strings and arbitrary remarks are not substituted into it. |
| Severity | Default observability severity. |
| Recovery | Descriptor recovery hint. Retry remains a separate decision that also considers idempotency, stage, and budget. |
| Backtrace | Whether canonical construction may capture a backtrace. |
| Exposure | `Public` permits schema-approved public fields; `Generic` suppresses all dynamic public fields. |
| Remoting | Numeric RocketMQ remoting response code. |
| gRPC | RocketMQ gRPC payload code and transport status. |
| HTTP | HTTP status number. |
| CLI | Process exit code. |
| Fields | Ordered context schema encoded as `name:visibility:type:maximum`; `None` means no text-length bound applies to that non-text value. |

Context visibility is part of the descriptor contract. `Public` values may
enter `PublicErrorView`; `Diagnostic` values are restricted to
`DiagnosticView`; `SecretPresenceOnly` records only a redacted presence marker.
Neither view exposes the typed source, caller location, or backtrace. Trusted
code follows the typed chain through `std::error::Error::source()`.

## Boundary and compatibility contract

- RocketMQ remoting numeric response codes and existing response headers are
  compatibility surfaces. A catalog refactor must not renumber them, drop
  correlation/header data, or replace a protocol-specific fixed outcome with a
  generic response.
- gRPC payload/status, HTTP status, and CLI exit mappings are descriptor-owned.
  Corrections require an intentional compatibility review and focused golden
  tests; rendered source text never selects a mapping.
- Public messages are fixed, bounded catalog text. Dynamic context is admitted
  only by the ordered field schema and its visibility.
- Catalog codes are unique and exact-match only. Unknown, malformed, or
  transitional uppercase codes do not resolve.
- Adding, removing, or changing a descriptor requires updating its declarative
  definition, `ALL_DESCRIPTORS`, and the exact snapshot test in the same change.
