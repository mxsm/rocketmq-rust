# 运行时架构与不变量

[English](ARCHITECTURE.md)

本文说明内部状态的所有权和执行顺序约束。接入方式、API 选择与验证命令见[README](README-zh_cn.md)。

应用入口拥有 `RuntimeOwner`；组件接收 `ChildServiceContext` 或更窄的能力接口。任务作用域管理生命周期，资源预算负责显式资源核算，两者不能相互替代。受管保留字节数表示资源预留，不代表分配器用量、RSS 或操作系统内存限制。

## 状态职责

| 职责 | 实现 | 不变量 |
| --- | --- | --- |
| 运行时组装 | [所有者](src/owner.rs)、[服务上下文](src/service_context.rs) | 子上下文共享所有者的运行时和进程资源。 |
| 任务准入与提交 | [提交](src/task_group/submission.rs) | 任务注册和句柄安装使用所有者的准入门控。 |
| 任务最终结算 | [完成处理](src/task_group/completion.rs) | Future 销毁先于失败统计和完成状态发布。 |
| 活跃任务与子组注册 | [注册表](src/task_group/registry.rs) | 子组链接使用弱引用；存活的后代持有其祖先。 |
| 截止时间与关闭结果保留 | [协调器](src/task_group/shutdown.rs)、[任务组门面](src/task_group.rs) | 后续调用不能延长已接受的截止时间，也不能替换已发布的报告。 |
| 阻塞准入与执行 | [准入](src/blocking/admission.rs)、[执行器](src/blocking/executor.rs) | 受管通道共享一个全局容量上限；运行中的闭包持有许可直到退出。 |
| 资源预留与动态代次 | [预算](src/resource_budget/budget.rs)、[动态键](src/resource_budget/dynamic.rs)、[队列](src/resource_budget/queue.rs) | 资源预留沿祖先链核算；已关闭的代次拒绝新准入和转入的许可重绑定。 |
| 调度驱动任务与执行任务 | [调度任务](src/scheduled.rs) | 两者都属于调度器的任务组；入口决定取消操作的所有权。 |
| 聚合与有界任务扫描 | [任务诊断](src/task_group/diagnostics.rs) | 本地计数不包含子组；有界详情明确报告截断。 |
| 诊断结构与采集 | [诊断](src/diagnostics.rs) | V1/V2 公开类型和传输字段名称保持稳定。 |
| 脱敏转换 | [转换](src/diagnostics/conversion.rs) | 标签来自类型化身份，不依赖向量位置；转换不执行业务 I/O。 |
| 进程生命周期转换 | [服务生命周期](src/service_lifecycle.rs) | 就绪状态、终止状态和首次关闭请求由状态管理逻辑决定。 |
| 健康探针传输与路由 | [探针](src/service_lifecycle/probe.rs) | 路由调用生命周期 API，不直接修改状态原子变量。 |
| 元数据准入与发布 | [元数据 actor](src/metadata_io.rs) | actor 状态通过统一协调协议管理等待者、保留字节数和代次顺序。 |
| 元数据目标身份与退役 | [目标注册表](src/metadata_target.rs) | 同一所有者下的 actor 共享目标历史；只有通过退役检查后才能复用槽位。 |
| 原子替换与持久性 | [文件系统](src/metadata_io/filesystem.rs) | 平台操作不修改 actor 状态或诊断结构。 |

状态应由原有所有者管理，能力通过既有公开门面模块暴露。拆分实现文件不能引入第二个状态所有者。新增任务分类时必须更新穷尽的 `TaskKind` 映射和传输转换；任务类型数组与遍历共用同一个私有枚举。

## 完成与关闭顺序

任务完成记录的是已注册 Future 的销毁，不代表业务成功。销毁先于失败统计和完成状态发布，包括首次轮询前中止，以及销毁期间发生 panic 的情况。 `TaskGroup::wait_task` 将不存在的本地任务视为已完成； `abort_task_and_wait` 对不存在的任务返回 false。

`OperationOutcome` 独立于 `ShutdownReport.completed`，记录每个已接受操作任务的结果：正常返回、操作取消、截止时间到达、所有者取消、panic，或其他结果尚未确定前发生的中止。其终结器只在用户 Future 销毁后发布结果。被拒绝的提交不会增加六项结果计数；操作仅保留这些计数，不保留逐任务的结果历史。排空操作忽略所有者取消，直到已接受的工作完成、被操作取消、到期或被显式中止。

关闭协调器封闭准入并保留已发布的结果。立即关闭报告不能确认 Future 已销毁或最终 I/O 已完成；需要最终 I/O 的服务必须通过协作式清理完成这些工作。各入口的保证见[关闭 API 契约](README-zh_cn.md#服务生命周期与关闭)。

阻塞观察者超时不会释放真实闭包占用的容量，也不会确定其执行结果。元数据被接受不表示已持久化，观察者超时也不表示已回滚。结果未知的写入仍须核实和协调其实际状态。

已关闭的动态代次拒绝准入和转入的许可重绑定，现有许可仍可释放或迁出。队列核算遵循[出队 API 的转移策略](README-zh_cn.md#资源预算与队列)。

## 观察边界

`ServiceLifecycleObserver` 只能在进程处于 Starting 状态时安装一次。状态变更与观察者安装共享一个短暂的同步边界；回调在全部生命周期锁释放后执行。只有已提交的变更才发出事件。并发转换可能导致回调乱序到达，因此每个事件都标明实际的前后状态。回调必须简短、非阻塞且不发生 panic；不能执行 I/O 或刷新导出器。导出器的关闭由应用组装入口负责。

`MetadataIoObserver` 和按指定名称观察的 `ScheduledTaskObserver` 使用弱引用，因此诊断使用方不会成为写入或执行的所有者。元数据注册表容量限制其资源扫描范围；调度查询成本与组件提供的固定名称集合大小成正比。

## 调度边界

普通和绑定操作的固定延迟适配器共享执行与最终结算逻辑，其外层取消操作仍由不同的所有者管理。旧版固定频率和 Cron 协议保留各自的时间语义。调度策略和兼容字段见[入口对照表](README-zh_cn.md#周期任务)。

使用方特有的排空顺序与持久化策略记录在对应组件文档中；参见 [Broker 事务维护](../rocketmq-broker/README-zh_cn.md#事务维护)。

## 采样成本与一致性

服务上下文的 V1/V2 采样直接从注册表读取阻塞聚合值，不会为各个阻塞任务分配名称或详情对象。显式的 `BlockingExecutor::snapshot` API 保留完整详情契约。任务子树计数和本地计数来自同一次遍历。

最大存续时间、长时间运行阈值和组计数需要扫描被观察条目；聚合采样不会在任务提交或完成路径上维护额外计数器。扫描在每个已访问的注册表条目内保持一致，但不构成跨任务组或阻塞通道的全局原子快照。因此，并发变更可能在不同时刻被观察到。本地计数计入同一次遍历的子树总数。

详情扫描与输出预算只限制详情部分，不限制聚合存续时间扫描。采样准备、计时范围和分配测量见[基准测试的测量边界](README-zh_cn.md#基准测试的测量边界)。

## 元数据目标退役

目标注册仅在进程内有效，不提供跨进程锁或崩溃恢复保证。[所有者计划](src/owner.rs) 接受非零的元数据目标容量，默认值为 4,096。空闲历史和被隔离的历史均占用槽位。每个 actor 还按相同容量独立限制其保留资源缓存：其他 actor 将共享历史退役时，不能让旧 actor 的墓碑条目无限增长。

正常替换 actor 会继承目标身份、资源所有权和已确认的代次。显式退役遵循不同的契约：准入关闭且协调器完成后，注册表以原子方式检查身份、已持久化代次、是否仍有有效写入权限，以及是否存在待协调状态的隔离标记。只有检查通过，新身份才能复用路径和槽位。仍开放的旧 actor 不能重新绑定已退役的身份；需要替换这些 actor 才能释放其墓碑条目。已完成的回执保留原始结果，不持有写入者。使用更新代次证明旧写入的状态前，必须先比较回执与 actor 的目标身份。

注册表统计提供容量、保留历史数、有效所有者数、空闲历史数、被隔离目标数和剩余容量，不暴露路径。被隔离目标与有效所有者的计数可以重叠。提交结果未知的目标会继续保持隔离：运行时不提供与格式无关的通用恢复，也不提供无条件清除隔离标记的操作。
